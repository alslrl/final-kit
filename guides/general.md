# 범용 흐름 (과제 유형 G: 서비스 구축형 흐름이 맞지 않을 때)

메인이 과제 유형을 G로 판단하고 내가 확정하면 메인은 이 파일을 따른다. AGENTS.md의 "요구사항", "계획", "확인" 절 중 묶음·PLAN 교차 확인·verify 명령 절차는 쓰지 않는다. "공통", "세션과 역할", "원장", "소통", "결정", "시간", "커밋" 절은 그대로 지킨다.

## 1. 목표와 완료 기준 (메인)
- 과제가 요구하는 것을 한 문장으로 쓰고, 완료 기준을 3~7개로 REQUIREMENTS.md 표에 적는다. 줄마다 출처(파일:줄)와 확인 방법(재계산 / 실행 / 내가 봄)을 쓴다.
- 산출물(파일, 보고서, 코드, 답안, 발표 자료 등)의 이름과 형식을 과제 문서에 적힌 그대로 적는다.
- 나에게 보여 주고 확인받는다. 애매한 것은 ops/OPEN.md에 적고, 담당자가 있으면 interview 세션으로 묻는다.

## 2. 같이 파악하고 세션 나누기 (메인과 나)
- 세션 구성은 미리 정해져 있지 않다. 메인은 나와 이야기하며 과제를 같이 파악한다. 내가 이해한 내용을 말하면 틀리거나 빠진 부분을 짚는다.
- 일을 서로 기다리지 않는 덩어리로 나누고 세션 구성을 제안한 뒤 멈춘다. ops/SESSIONS.md 계획 절에 이 형식으로 적는다:
  | 등록 이름 | 역할 | 맡는 것 | 고칠 파일·폴더 | 산출물 | 끝났다고 보는 기준 | 보내는 곳 | 붙여 넣을 첫 문장 |
  - 역할은 기존 카드(research, study, verify, docs, interview, build)가 맞으면 그것을 쓰고, 맞는 카드가 없으면 work를 쓴다. work 세션 등록 이름은 work-<맡는 것>이다.
  - 고칠 파일·폴더는 세션끼리 겹치지 않게 나눈다. 같은 파일을 여러 세션이 고쳐야 하면 한 세션에 몰거나 메인이 통합한다.
  - 첫 문장 예: "너는 work-데이터정리 세션이야. 역할은 work. ops/SESSIONS.md 계획 절의 네 줄을 따라."
- 내가 고치거나 정하면 ops/DECISIONS.md에 남기고, 내가 세션을 연다. 메인이 직접 할 작은 일은 메인의 서브에이전트로 병렬 처리한다.
- 진행 중에 일이 새로 생기거나 나눔이 안 맞으면 메인이 세션 추가·합치기를 다시 제안한다.

## 3. 실행
- 각 세션은 맡은 일의 산출물을 자기 파일·폴더에 남기고, 끝나거나 막히면 send.sh로 메인에 한 줄 알린다. 메인은 ops/STATE.md를 고치고 결과를 모은다. 계산·집계는 코드로 하고 결과 파일을 남긴다.
- 막히거나 방향을 바꿔야 하면 같은 방법을 반복하지 말고 나에게 선택지 2~3개와 추천을 보여 준다.
- 모르는 개념·배경이 필요하면 docs/QUESTIONS.md에 적고 research 세션에 맡긴다.

## 4. 확인
- 완료 기준마다 확인 방법을 실행해 상태(PASS / FAIL / NOT_RUN / HUMAN_CHECK)를 표에 적는다. 숫자는 원본에서 따로 다시 계산한다.
- 확인이 무거우면 verify 세션에 "완료 기준 <번호> 확인"을 보내 맡긴다.

## 5. 마무리 (내가 "마무리"라고 하면)
- 결과 요약: 무엇을 했나 / 핵심 결과(숫자와 출처 파일) / 근거 / 한계와 다음 단계.
- 제출 문서·발표 원고·서술형 대비는 AGENTS.md 규칙대로 docs 세션(없으면 메인)이 한다.
