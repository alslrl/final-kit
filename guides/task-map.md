# 과제 지도 안내 (메인이 시작할 때, 또는 내가 "과제 지도"라고 할 때 읽는다)

- README와 데이터를 읽고(메인은 서브에이전트 결과를 모아) docs/TASK_MAP.md를 만든다.
- 목적은 내가 큰 그림을 한눈에 잡는 것이다. 전체 40줄 이내로 쓴다. 파일은 실제 경로·이름 그대로 쓰고(한글 이름은 괄호로), 파일:줄 출처, 열 이름 전체 목록, 빈칸·중복 같은 품질 집계, 산출물 필드 목록은 쓰지 않는다(요구사항 표와 인터뷰 몫이다).
- 데이터는 파일별 행 수, 파일을 잇는 열, "한 건 따라가기"에 쓸 대표 1건의 관련 행만 보고, 원본 행 전체를 출력하지 않는다.
- 내가 "내가 이해한 건 이거야"라며 요약을 보내면, 틀리거나 빠진 부분만 짧게 짚는다.

````markdown
# 과제 지도
## 1. 한 문장
누가 / 무엇 때문에 / 무엇을 만드나

## 2. 폴더와 파일
```
README.md                 과제 안내
data/orders.csv           (주문, 1,200행) 한 행 = 주문 한 건   ← 예시
data/....csv              (한글 이름, 행 수) 한 행 = 무엇
schema/....json           (결과 형식)
(이미 있는 코드·폴더가 있으면 한 줄씩)
```

## 3. 큰 그림
```
[입력]                         [처리]            [결과]
data/파일.csv (한글 이름) ─┐
data/파일.csv (한글 이름) ─┼─→ 핵심 처리 ───→ 결과물 ─┬→ 화면·산출물 (무엇이 보이나)
data/파일.csv (한글 이름) ─┘   (핵심 조건)            └→ 화면·산출물 (무엇이 보이나)
보조 파일 ─────────────────────────────────────────────→ 어디에 쓰이나
연결: 파일.열 = 파일.열 / ...
```

## 4. 한 건 따라가기
```
대표 1건 (핵심 속성)
 → 처리 단계: 무엇을 보고 무엇이 정해지나
 → 결과·화면: 어떻게 보이나
```
(한 줄에 한 단계, 실제 값으로)

## 5. 어려운 곳
- 결과를 틀리기 쉬운 부분, 3개 이하, 한 줄씩
````
