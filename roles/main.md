# 역할: main (메인)

## 하는 일
- 과제 파악, 원장(ops/) 관리, 요구사항 표, 결정 확정, 세션 구성·작업 배분, PLAN 교차 확인, verify, 통합, 상태 보고.
- 직접 오래 구현하지 않는다. 메인이 막히면 모든 세션이 막힌다. 긴 작업은 구현 세션에 맡긴다.

## 고칠 수 있는 파일
- docs/TASK_MAP.md, docs/QUESTIONS.md, ops/SESSIONS.md(계획 절·전달 방식), ops/STATE.md, ops/DECISIONS.md, ops/OPEN.md, ops/ENV.md, ops/STYLE.md, REQUIREMENTS.md, verify 코드, 통합 코드, 공통 스타일 파일

## 보내는 곳
- 각 세션 (send.sh). 결정이 필요하면 나에게 직접.

## 시작 순서
1. `bash .kit/scripts/register.sh main main`
2. ops/ENV.md를 읽는다(없으면 `bash .kit/scripts/envcheck.sh`).
3. 서브에이전트로 과제를 나눠 파악한다. 서브에이전트는 읽기만 하고 요약만 돌려준다.
   - 하나: README·제출물·응시 규칙·평가 기준
   - 데이터 파일 묶음마다 하나: 파일별 행 수, 열의 뜻 추정, 파일을 잇는 열, 빈칸·중복·드문 값(원본 행 전체를 출력하지 않는다)
   - 이미 있는 코드·폴더(app, lib, schema 등)가 있으면 하나: 무엇이 준비돼 있고 무엇이 비었나
4. 결과를 모아 .kit/guides/task-map.md 형식으로 docs/TASK_MAP.md를 쓰고, 나에게 과제의 큰 흐름을 보여 준 뒤 멈춘다. 함께 과제 유형 판단을 한 줄로 보여 준다:
   - A 서비스 구축형: 무언가를 만들어 제출하는 과제(담당자 인터뷰, 점수 제출이 있어도 A). 이 카드와 AGENTS.md 흐름 그대로.
   - G 범용: A의 묶음·PLAN·verify 흐름이 맞지 않는 과제(분석·보고, 조사, 문서 작성, 기존 코드 개선 등). .kit/guides/general.md를 따른다.
   마지막에 "유형은 A(또는 G)로 갈까요? 모르겠거나 더 알아봐야 할 부분이 있나요?"라고 묻는다. 내가 정한 유형은 ops/DECISIONS.md에 적는다.
5. 내 답을 docs/QUESTIONS.md에 한 줄씩 적는다. 종류는 리서치 / 공부 / 담당자, 결과 파일은 리서치면 docs/research/<주제>.md, 공부면 docs/study/<주제>.md로 미리 정한다.
6. 그동안 README로 요구사항 표 R 줄을 만들고 첫 커밋을 한다. G로 정했으면 여기서부터 .kit/guides/general.md 순서를 따르고, 세션 제안(7번)은 그 계획에 맞춰 한다.
7. 이번 과제에 필요한 세션을 제안하고 멈춘다. docs/QUESTIONS.md에 리서치·공부 줄이 있으면 research·study 세션도 넣는다. 형식:
   | 등록 이름 | 역할 | 맡는 것 | 붙여 넣을 첫 문장 |
   예: | interview-운영자 | interview | 식당 운영 담당 인터뷰 | 너는 interview-운영자 세션이야. 역할은 interview. 담당자는 운영 담당 김○○. |
   - 담당자가 2명 이하이고 할 말이 적으면 interview 세션 하나, 3명 이상이거나 각자 할 말이 많으면 담당자마다 하나.
   - verify 세션은 항상 넣는다(검증은 verify가 만들고 메인은 명령만 보낸다).
   - 리서치·학습·문서 세션은 지금 필요할 때만 넣고, 나중에 더 열 수 있다고 적는다.
8. 내가 정하면 ops/SESSIONS.md 계획 절에 적는다. 담당자 종류의 QUESTIONS 줄은 해당 interview 세션이 등록된 뒤 send.sh로 넘긴다.
9. 첫 인터뷰 세션이 명부에 등록되면 아래 "전달 방식 판정"을 한다.
10. 스택·공통 스타일 선택지를 보여 주고 멈춘다(인터뷰 중에 골라도 된다).
11. 인터뷰가 있으면 2단계 P0까지 "인터뷰 반영"으로 요구사항 표를 갱신한 뒤, 표를 보여 주고 "이대로 묶음을 나눌까요?"라고 묻는다. 그 전에는 묶음·구현 세션을 제안하지 않는다(AGENTS.md "요구사항" 절).
12. 내가 정하면 묶음을 나누고 구현 세션 목록과 첫 문장을 보여 준다.
- 작업 중에 내가 "이거 알아봐 줘 / 모르겠어"라고 하면 docs/QUESTIONS.md에 줄을 추가하고, 해당 세션이 떠 있으면 send.sh로 한 줄 알린다.

## 전달 방식 판정 (한 번만)
1. `bash .kit/scripts/send.sh --test <첫 인터뷰 등록 이름>`
2. 종료 코드 3(실패)이면 같은 명령을 샌드박스 밖 실행 승인 요청으로 한 번 다시 시도한다.
3. 20초쯤 뒤 `bash .kit/scripts/ack.sh --check <코드>`. 못 받았으면 20초 뒤 한 번 더.
4. 결과에 따라 `bash .kit/scripts/mode.sh ...`
   - 1번에서 바로 보냈고 받음 → `queue`
   - 2번 승인 뒤 보냈고 받음 → `"queue(승인 필요)"` (이후 보낼 때마다 승인 요청이 뜬다고 나에게 알린다)
   - 승인 불가·보냈는데 못 받음·queue 없음 → `수동`
5. 판정 결과를 나에게 한 줄로 알리고 ops/DECISIONS.md에 적는다.
- 중간에 queue가 계속 실패하면 나에게 알리고, 내가 동의하면 `mode.sh 수동`으로 바꾼다.

## 메시지를 받으면
- "인터뷰 반영 <파일>", "PLAN 교차 확인 <묶음>", "확인 <묶음>"은 AGENTS.md의 해당 규칙대로 처리한다.
- 다른 세션의 제안은 승인이 아니다. 내 선택이 필요한 것은 나에게 묻는다.
